## Verified evidence and remaining unknowns

The official public [Solflare SDK README](https://github.com/solflare-wallet/solflare-sdk)
documents connect, disconnect, Solana transaction signing and message signing.
That document does not establish a Perps order API, underlying venue, collateral
bridge or unattended derivatives signer. None of those are assumed from the UI.
Direct requests to Solflare documentation are currently denied by the development
environment's HTTP proxy (403). A network configuration draft was saved for
solflare.com, www.solflare.com, help.solflare.com, docs.solflare.com and
perps.solflare.com. The configuration service additionally reported the existing
secret destination backboard.railway.com. Review/Save and Publish apply the draft;
the save itself does not grant network access or deploy Railway.

Before implementing real execution, establish from official documentation:

1. The actual venue and supported market-data/order/account APIs.
2. How the owner authorizes an unattended trading agent, scopes/revokes it, and
   signs that venue's orders. The existing Solana key is not assumed compatible.
3. Supported collateral, account mapping and funding/withdrawal path. A screenshot
   balance is not live account evidence; no SOL/USDC bridge or deposit is sent.
4. Per-market leverage/margin limits, tick/lot precision, fees, funding, liquidation
   estimates and order recovery semantics.
5. Exchange-resident reduce-only stops, cancellation/partial-fill behavior and
   protection that remains effective while the AI or Railway is unavailable.

The requested AI contract is LONG/SHORT/HOLD, collateral size, leverage and SL
chosen by the AI from current market/account observations. Venue leverage limits
must be read from the API, not copied from the screenshot. Preserve 0.05 SOL gas
on the Solana funding wallet. Telegram must report accepted orders separately
from confirmed fills and distinguish unrealized PnL, funding and realized PnL.

## What this deployment does now

Docker selects `TRADING_PRODUCT=solflare-perps`. This puts the app in a clearly
labeled verification/migration state; it does not enable derivatives trading.
New spot BUY requests are blocked in the parent before preparation and signing,
including requests from cached browser sessions or old AI intents. An already
signed transaction is still reconciled by its original signature.

Existing spot positions, receipts, inventory reconciliation, AI-selected stop
monitoring and authorized SELL/HOLD remain available with the existing signer.
No forced liquidation or transfer is generated by the migration. Resume cannot
re-enable meme entries. Existing PnL, wallets and Telegram configuration are
retained and explicitly labeled as the legacy spot book.

`product.perpsEnabled`, `product.signingVerified` and
`product.collateralVerified` remain false. Model API verification is a separate
fact and must not be shown as a successful connection to Solflare Perps.
